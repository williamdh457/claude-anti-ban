# 02 · 访问检测：ip.net.coffee/claude 逐项判读

> **每次打开 Claude 之前，先打开这个页面。** 这是整份手册的核心动作，也是唯一能把「我以为我配好了」变成「确认配好了」的手段。
> 地址：<https://ip.net.coffee/claude/>

页面结构：左侧一组检测卡片（Claude 评分 / GPT 检测 / 网络连通 / DNS 泄露 / WebRTC / UDP / Cloudflare / 全球 Ping / 服务状态），主区域是 Claude 专项结果，底部是设备信息与历史记录。

---

## 一、看什么（按重要性排序）

### 1. 三个出口 IP 必须一致 ⭐️⭐️⭐️⭐️⭐️

页面同时显示：

| 名称 | 含义 |
|---|---|
| **中国出口 IPv4** | 从中国大陆方向看到的你的 IP |
| **Cloudflare 出口 IP** | Cloudflare 边缘节点看到的你的 IP |
| **Claude AI 出口 IP** | 实际访问 Claude 时用的出口 |

**判定：三个必须是同一个 IP。**

- 出现两个不同 IP → 分流失效（某类流量没走代理）或 IPv6 偷跑；
- 出现中国大陆 IP → 分流规则漏了，或者你开着「智能分流/直连」；
- 出现 IPv6 → 立刻关 IPv6（见 `04-timezone-locale.md`）。

> 页面对 IPv6 有专门提示：**不建议用 IPv6 访问 Claude Code**，部分检测结果会不完整。

### 2. Trust Score（信任评分）⭐️⭐️⭐️⭐️

0–100 分，越高越可信。

| 分数 | 判读 |
|---|---|
| 80–100 | 优秀，可长期用 |
| 60–79 | 可用，注意别再叠加其他风险项 |
| 40–59 | 偏差，建议换 IP |
| < 40 | 不要用这个 IP 注册或付款 |

配套看下面四行标记，**任何一项命中都要处理**：

- **VPN** — 识别为商业 VPN 出口
- **代理 (Proxy)** — 识别为代理
- **Tor** — Tor 出口节点，直接放弃
- **机器人 (Crawler)** — 被标记为爬虫段
- **滥用记录** — 该 IP 段有历史滥用

### 3. IP 属性与地区 ⭐️⭐️⭐️⭐️

| 属性 | 评价 |
|---|---|
| 住宅 / ISP（家宽） | 最优，几乎不触发验证 |
| 原生 IP（非广播段机房） | 次优，长期固定可用 |
| 广播 IP | 较差，地理位置常被判错 |
| 数据中心常见段（AWS/GCP/Azure/Vultr/DO…） | 一般，需靠长期稳定 + 其他项全绿来补 |
| 共享代理 IP | 最差，直接换 |

**地区**必须在 Claude 支持范围内。美国最稳，其次日本、新加坡、欧洲部分国家。香港、澳门、俄罗斯、伊朗等地区不要用。

### 4. Claude 可用性检测 ⭐️⭐️⭐️

分别测 `claude.ai` 和 `anthropic.com` 的连通与延迟。

- 亚洲出口 100–150 ms 正常；
- 美西 150–250 ms 正常；
- 超过 400 ms 或间歇超时 → 线路绕路，换机房。

### 5. DNS 泄露 ⭐️⭐️⭐️⭐️

显示「状态」和「DNS 出口 IP」。

- **通过**：DNS 出口 IP = 你的代理出口 IP；
- **泄露**：DNS 出口 IP 是中国大陆或与你出口不一致 → 修（见 `05-dns-leak.md`）。

这是最容易被忽略、又最容易被风控抓到的一项：连接 IP 在海外，DNS 查询却从国内发出，地域直接矛盾。

### 6. WebRTC / UDP 泄露 ⭐️⭐️⭐️⭐️

显示「状态」和「UDP 出口 IP」。

- **通过**：UDP 出口 IP = 代理出口 IP；
- **泄露**：UDP 出口 IP 是你的真实 IP → 修（见 `06-webrtc-leak.md`）。

### 7. 设备信息（时区 / 语言 / 指纹）⭐️⭐️⭐️⭐️⭐️

页面底部「Claude AI出口IP用户设备信息」卡片会列出浏览器真实读到的：

| 项 | 期望 |
|---|---|
| **时区** | 显示「时区一致」；出现黄标「不推荐使用中国大陆时区」= 高危 |
| **语言** | 与 IP 地区匹配（美国 IP → `en-US`） |
| 操作系统 / 浏览器 | 正常桌面浏览器，不要是 headless / 非常见 UA |
| 触屏 | 桌面环境应为「否」 |
| 网络类型 | 与代理链路一致 |
| Do Not Track | 不强求，但别开一堆隐私插件搞出怪异组合 |
| WebGL 渲染器 | 真实 GPU，不要 `SwiftShader` / `llvmpipe`（虚拟机常见！） |
| Canvas 指纹 | 稳定即可，**不要每次刷新都变**（随机指纹插件是负分） |

> 虚拟机里如果没装显卡驱动，WebGL 会显示 `SwiftShader`——这本身就是一个「非真实用户」特征。Hyper-V 里建议开启增强会话、装好集成服务，或用真实宿主机跑浏览器。

### 8. 历史记录

页面会记录你每次检测的出口 IP（仅本地浏览器存储）。

用途：**自查是否跳变**。短时间内出现 3 个以上不同国家的 IP = 典型「账号被盗用」画像。

## 二、判读流程（照着走）

```
打开检测页
   │
   ├─ 三个出口 IP 一致？ ── 否 → 查分流 / 关 IPv6 / 开 TUN
   │        │是
   ├─ Trust Score ≥ 60？ ── 否 → 换 IP（工单）
   │        │是
   ├─ 有 VPN/Proxy/Tor/Crawler 标记？ ── 是 → 换 IP 或换商家
   │        │否
   ├─ DNS 通过？ ── 否 → 修 DoH / 关运营商 DNS
   │        │是
   ├─ WebRTC/UDP 通过？ ── 否 → 关 UDP 直通 / 改浏览器 flag
   │        │是
   ├─ 时区一致？ ── 否 → 改系统时区（不是改插件！）
   │        │是
   ├─ 语言匹配？ ── 否 → 调浏览器语言列表
   │        │是
   └─ 全绿 → 才打开 claude.ai
```

## 三、常见误判

| 现象 | 真相 |
|---|---|
| 「我明明挂了代理，为什么中国出口 IPv4 还是国内？」 | 代理没开 TUN，或者浏览器走了直连规则；也可能是 QUIC/UDP 走了直连 |
| 「Claude 出口 IP 和 Cloudflare 出口 IP 不一样」 | 正常现象**仅当**你有分流（不同域名走不同节点）；否则说明规则不完整 |
| 「时区显示不一致，但我改了时区」 | 浏览器没重启；或者你改的是浏览器插件时区，不是系统时区 |
| 「Trust Score 很低但 IP 是住宅」 | 住宅段被前用户污染；换 IP 或换段 |
| 「机房 IP 是不是一定被封？」 | 不是。作者用机房 IP 稳定一年。关键在**独享 + 固定 + 其他项全绿** |
| 「语言改成英语了还是黄」 | 浏览器语言列表里还残留 `zh-CN`；要删掉而不是往下移 |
| 「WebRTC 一直泄露」 | 代理端 UDP 直通没关；或浏览器 flag 没生效（需重启浏览器） |

## 四、把检测变成习惯

推荐做法：

1. 把这个页面设为浏览器启动页 / 书签栏第一个；
2. 每次开机、每次换节点、每次出差换网络，先跑一遍；
3. 用 `scripts/check_env.sh` / `check_env.ps1` 做命令行快检，页面做最终确认；
4. 出问题先看「历史记录」有没有异常跳变——很多封号是跳变引起的，不是 IP 脏。
