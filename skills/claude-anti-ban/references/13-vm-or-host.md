# 13 · 虚拟机还是宿主机：先选方案，再动手

> 这一步**不要替用户决定**。方案选错，后面所有配置都要重来。
> 判断标准只有三个：**这台机器上有多少「脏东西」、你有多怕再被封、你能不能接受多一层窗口。**

---

## 一、一句话结论

| 你的情况 | 选 |
|---|---|
| 号被封过、或者这台机器登过好几个号 | **A 虚拟机** |
| 要长期挂 Claude Code、跑自动化 | **A 虚拟机** |
| 只偶尔用网页版聊天，机器很干净 | **B 宿主机** |
| 想省事、内存只有 8 GB | **B 宿主机** |
| 既想日常方便，又想长期稳 | **C 混合** |

---

## 二、三个方案详解

### A. 虚拟机方案（Hyper-V）

**做法**：Hyper-V 里一台干净 Windows，只装浏览器 + VSCode + Claude 桌面端。时区、语言、代理全在这台机器里统一。一号一机。

**好处**

| 收益 | 说明 |
|---|---|
| 封号概率最低 | 环境里没有任何历史污染：没有旧 cookie、没有别的号、没有国产软件、没有国产模型中转 |
| 可回滚 | 打检查点（快照），环境脏了 30 秒回到干净状态，不用重装系统 |
| 隔离彻底 | 宿主机上装什么、登什么号，都不影响它 |
| 可复制 | 想养小号，复制一份 VHDX，改个名字就是新机器 |
| 画像自洽 | 时区 / 语言 / 浏览器 / 出口 IP 全在一个盒子里，不会互相打架 |

**代价**

| 成本 | 量级 |
|---|---|
| 内存 | 常驻 6–8 GB（宿主机建议 16 GB 起） |
| 磁盘 | 80–100 GB |
| 首次搭建 | 40–60 分钟（下载 ISO + 装系统 + 配置） |
| 日常不便 | 多一层窗口；复制粘贴要开增强会话；传文件要额外设置 |
| 性能 | 比宿主机低 10–30%，Claude Code 编译大项目会慢一点 |
| GPU | 默认无 3D 加速，WebGL 可能显示 `SwiftShader`（本身是个异常指纹，需装集成服务缓解） |

**适合**：被封过、要长期用、机器配置够、能接受折腾一次。

---

### B. 宿主机方案

**做法**：直接在现有系统上配好时区、语言、代理、DNS、WebRTC，清掉旧痕迹，一号一机。

**好处**

| 收益 | 说明 |
|---|---|
| 零额外开销 | 不占额外内存磁盘 |
| 最顺手 | Claude Code 直接跑在项目目录，文件、IDE、终端全在一起 |
| 配置快 | 20 分钟能全部搞定 |
| 性能满血 | 编译、索引、跑测试都是原生速度 |

**代价**

| 风险 | 说明 |
|---|---|
| 环境不可控 | 你装过的每一个软件、每一个浏览器扩展、每一个国产工具，都是画像的一部分 |
| 清不干净 | 注册表、缓存、日志、索引、云同步，总有残留 |
| 不可回滚 | 环境脏了只能手工清；号废了整台机器都要重新收拾 |
| 一号一机的纪律难守 | 顺手就登了第二个号，顺手就装了国产模型插件 |
| 多账号互相污染 | 同一浏览器 Profile 登过 A 号再登 B 号，cookie 交叉 = 关联 |

**适合**：机器干净、只用网页版、配置不高、不想折腾。

---

### C. 混合方案（多数人的实际选择）

```
日常聊天 / 轻量任务  → 宿主机（保持干净：不装国产 AI 插件、不接中转、不登第二个号）
Claude Code / 长期跑 → 虚拟机（干净基线 + 检查点 + 一号一机）
```

要点：

- 两个环境用**同一个出口 IP**（同一个节点），不要一个走 A 节点一个走 B 节点；
- **不要同时登录同一个账号**（一边网页一边 CLI 也算两台设备，但同一 IP 下通常没问题；跨 IP 就有风险）；
- 小号全部放虚拟机，宿主机只留主号。

|---|---|---|---|
| 防封效果 | ★★★★★ | ★★★ | ★★★★ |
| 使用便利 | ★★ | ★★★★★ | ★★★★ |

## 四、Agent 该怎么问（话术模板）

```text
在开始配置之前，你需要先选一个方案。我把利弊列出来，你选完我再动手。

A. 虚拟机（Hyper-V）
   防封效果最好，环境可回滚、可复制。
   代价：占 6–8 GB 内存、80 GB 磁盘；首次搭建约 1 小时；
        日常多一层窗口，传文件要额外设置；性能略低。

B. 宿主机（直接在当前系统配）
   最方便、零额外开销、性能满血。
   代价：环境里的历史污染清不干净；不可回滚；一号一机的纪律容易破。

C. 混合
   日常聊天用宿主机，Claude Code 和长期任务放虚拟机。
   两个环境共用同一个出口 IP。

请回答：
1) 你的机器内存多大、磁盘剩多少？
2) 这个号以前被封过吗？这台机器登过几个 Claude 账号？
3) 你主要用网页版，还是 Claude Code？
4) 你更在意「不容易被封」还是「用起来方便」？

根据这四个答案我给你建议，你确认后我再开始。
```

### 建议映射

| 内存 | 被封过 | 主要用途 | 建议 |
|---|---|---|---|
| ≥16 GB | 是 | Claude Code | **A** |
| ≥16 GB | 是 | 网页版 | **A**（或 C） |
| ≥16 GB | 否 | Claude Code | **C** |
| 8 GB | 任意 | 网页版 | **B** |
| 8 GB | 是 | 任意 | **B + 彻底清理**，攒够内存再上 A |
| 任意 | 否 | 网页版 | **B** |

## 五、选 A 的前置检查（Agent 先跑这个）

```powershell
# Windows 版本
(Get-ComputerInfo).WindowsProductName
# 是否专业版及以上（家庭版不支持 Hyper-V）

# CPU 虚拟化
(Get-CimInstance Win32_Processor).VirtualizationFirmwareEnabled
# 或任务管理器 → 性能 → CPU → 「虚拟化：已启用」

# 内存 / 磁盘
[math]::Round((Get-CimInstance Win32_ComputerSystem).TotalPhysicalMemory/1GB,1)
Get-PSDrive C | Select-Object Used,Free

# Hyper-V 是否已装
Get-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V-All | Select State
```

任一项不满足就先解决，别硬上：

| 不满足 | 处理 |
|---|---|
| 家庭版 | 升级专业版，或走 B 方案 |
| 虚拟化未启用 | BIOS 里开 VT-x / AMD-V / SVM |
| 内存 < 16 GB | 走 B 方案，或加到 16 GB |
| 磁盘 < 100 GB | 清理，或外接盘 |

## 六、选 B 的前置检查

```bash
# 这台机器上有没有「脏东西」
ls ~/.claude 2>/dev/null && echo "有 Claude Code 历史"
ls "$HOME/Library/Application Support/Claude" 2>/dev/null && echo "有桌面端历史"
# 浏览器 Profile 数量（登过几个号）
ls ~/Library/Application\ Support/Google/Chrome/ 2>/dev/null | grep -c Profile
```

如果这台机器登过 2 个以上 Claude 账号 → **别选 B**，直接 A。清理能清本地痕迹，清不掉服务端已经建立的关联。

---

## 七、常见误区

| 误区 | 事实 |
|---|---|
| 「虚拟机里 IP 不一样，更安全」 | 错。虚拟机走宿主机网络，出口 IP 一样。虚拟机的价值是**环境隔离**，不是 IP 隔离 |
| 「虚拟机性能差，Claude Code 跑不动」 | 错。分配 4 vCPU + 6 GB，日常开发够用；只有大型编译会慢 |
| 「宿主机清理干净就等于虚拟机」 | 不完全。清理清不掉硬件指纹、已建立的账号关联、系统级残留 |
| 「虚拟机里可以随便登多个号」 | 错。一台 VM 一号，多号就多开 VM |
| 「复制虚拟机就能白嫖新号」 | 复制出来的机器硬件 ID 相同，**必须 `-GenerateNewId` 并改主机名**，且要换 IP 段、换账号 |
| 「虚拟机里 WebGL 是 SwiftShader 无所谓」 | 有关系。这是「非真实用户」特征。装集成服务、开增强会话能改善 |

## 八、决策速查（一屏看完）

```
内存 < 16 GB ────────────────→ B 宿主机
   │
   └─ 内存 ≥ 16 GB
        │
        ├─ 被封过 / 登过多个号 ──→ A 虚拟机
        │
        ├─ 主要跑 Claude Code ───→ A 或 C
        │
        └─ 只网页聊天、机器干净 ─→ B 宿主机
```
