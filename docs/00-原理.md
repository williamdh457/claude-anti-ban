# 00 · 原理：风控到底在看什么

> 你不需要「骗过」Anthropic，你只需要**不显得矛盾**。
> 正常用户的特征不是「完美」，而是「稳定、一致、符合所在地常识」。

---

## 一、风控画像的七个维度

| 维度 | 它看到什么 | 矛盾信号 |
|---|---|---|
| **出口 IP** | IP 归属地、ASN 类型（住宅/机房）、信誉分、滥用历史 | 一天换三个国家；共享机场出口；被标记 proxy |
| **系统时区** | 浏览器 `Intl` 与客户端本地调用读到的时区 | IP 在纽约，时区 `Asia/Shanghai` |
| **语言** | `navigator.languages`、`Accept-Language` | 美国 IP + 只有 `zh-CN` |
| **DNS** | 解析请求最终由哪台递归服务器发出 | 连接在美国，DNS 从国内发出 |
| **UDP / WebRTC** | STUN 拿到的公网 IP、内网 IP | 网页请求走代理，UDP 走本地 |
| **设备指纹** | Canvas、WebGL、UA、字体、屏幕、触屏 | 虚拟机里 WebGL 是 `SwiftShader`；随机化插件每次刷新都变 |
| **支付 / 身份** | 卡 BIN、账单国家、手机号、邮箱域名 | 美国 IP + 中国卡 BIN + 临时邮箱 |

任意两项互相矛盾，就构成一个「可疑」的加分项。加到阈值以上，就开始弹验证；再往上就是封。

---

## 二、为什么「挂了代理还是被封」

三个最常见的漏点：

### 1. 时区不看 IP

社区逆向披露（Claude Code 2.1.91，2026 年，未经官方证实但可自行验证）：客户端会读取**系统时区**判断用户是否来自中国大陆时区，并且这个判断**不依赖 IP**。路径至少两条：

- 时区名是 `Asia/Shanghai` / `Asia/Urumqi`；
- `ANTHROPIC_BASE_URL` 指向的中转站域名命中内置名单。

所以「代理骗得过服务器，时区骗不过自己的电脑」。

### 2. 分流漏域名

Claude Code 运行时不止访问 `claude.ai`，还会碰 CDN、OAuth、错误监控、AB 测试、客服 widget、NTP 校时。
漏一个域名 = 那部分流量直连 = 同一个账号出现两个出口。

### 3. IPv6 偷跑

代理规则大多只匹配 A 记录（IPv4）。Anthropic 同时有 AAAA 记录，IPv6 请求可能直接命中直连规则。
结果是「一个请求从日本出去，下一个从你家宽带出去」——双栈一撞，风控立刻升级。

## 三、连坐机制

Claude 的封号会**顺着 IP 传染**：

- 共享机场：几百人一个出口，邻居干了什么你不知道；
- 廉价机房段：整段被用来批量注册过 AI 账号，信誉已烂；
- 同一张卡给多个账号付款：支付层的关联比 IP 更硬。

所以选出口的第一原则不是「快」，而是 **独享 + 干净 + 固定**。

## 四、正常用户长什么样

| 特征 | 正常用户 | 高危用户 |
|---|---|---|
| IP 变化 | 家宽动态，偶尔变 | 一天跨三个国家 |
| 时区 | 与所在地一致，常年不动 | 与 IP 不符 |
| 语言 | 本地语言 + 英语 | 与 IP 地区不匹配 |
| 使用节奏 | 白天用、有间断、额度用不满 | 凌晨集中猛刷、额度打满 |
| 设备 | 一两台，长期不变 | 频繁换设备 / 多开 |
| 支付 | 一张卡、一个账号 | 一卡多号 / 虚拟卡 |

**结论**：不用装得像美国人，只要别像「一台机器在批量操作」。

---

## 五、本手册的策略

```
不追求「最干净的 IP」
追求「最一致的环境 + 最稳定的节奏」
```

具体就四件事：

1. **出口固定**：一台 VPS、一个节点、长期不变；
2. **身份对齐**：时区、语言、区域、DNS、UDP 全部跟着出口走；
3. **环境隔离**：虚拟机或干净宿主机，一号一机；
4. **节奏放慢**：先免费养号，再 Pro，再 Max，额度留余量。

这四件事做到，剩下的交给时间。

## 六、这套机制的边界

- 部分结论来自社区逆向与爆料，**未经 Anthropic 官方证实**；
- 风控策略会变，今天有效的做法明天可能调整；
- 本手册给的是「降低矛盾信号」的工程方法，不承诺「不被封」；
- 账号状态问题最终走官方申诉（`support.claude.com`），本地清理解决不了服务端记录。
