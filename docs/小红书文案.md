## 三、正文（主推版 · 832 字，可直接复制）

```
做 Claude 这一年，被限制过 3 次。
一开始以为是节点不行，换了一家又一家，还是不行。

后来才想明白：不是 IP 脏，是「画像自相矛盾」。

🚩 三个最容易被忽略的信号

1️⃣ 系统时区
IP 在纽约，系统时区写着 Asia/Shanghai。
Claude Code 读的是系统时区，不是 IP。
网络工具骗得过服务器，骗不过自己的电脑。

2️⃣ 分流漏域名
它不只用 claude.ai，还会碰 CDN、登录验证、错误上报、时间同步。
漏一个，就有一半流量从本地直连出去。
一个账号两个出口，风控直接标红。

3️⃣ IPv6 偷跑
分流规则大多只管 IPv4。
IPv6 那条路绕过去，从你家宽带出去了，你还不知道。

🛡️ 几条基础习惯，比换节点有用

· 一号一机，别在同一台电脑登第二个号
· 节点定了别乱换，一天换三个国家最像被盗号
· 新号先免费养 1–3 个月，别注册当天就冲订阅
· 额度留两三成，每月打满本身就是异常特征
· 别用临时号码、一次性邮箱、共享节点
· 一张卡只给一个号付款，支付层的关联比 IP 更硬
· 弹「验证」先别点，先看网络对不对
· 别把 Claude Code 接到来路不明的中转上

💡 所以我做了什么

把「查环境 → 清旧痕迹 → 搭节点 → 配分流（除白名单全走代理）
→ 时区语言按出口自动对齐 → 封掉 DNS 和 WebRTC 泄露
→ 需要就建一台干净虚拟机 → 九项验收 → 出一份 Word」
整套写成了一个自动化流程，交给 AI 它自己跑完，中间只问我 7 个选择题。

📄 最后只拿到一份文档
不是配置报告，是「每天开机 5 步 + 出问题对照表」。

⚠️ 个人经验，不构成使用建议
能降低「环境矛盾」的风险，但不保证不被限制。
最终看平台规则，遇到问题走官方申诉，别反复试登录。

这套流程我整理成了一份清单，之后会放到主页合集里。
感兴趣的可以关注一下，更新了会发出来。
```

## 六、承接怎么做（合规版）

小红书对「导流到个人」是全网最严的一档，**「评论区扣1私发」「私信我1领取」属于典型踩线**，正文和评论都别写。合规的做法只有一条：**站内承接**。

### 6.1 正文/评论区允许出现什么

| 允许 | 不允许 |
|---|---|
| 「之后会放到主页合集里」 | 「私信我 1 发你」 |
| 「感兴趣的可以关注一下」 | 「扣 1」「评论区留 1」 |
| 「评论区聊聊你的情况」 | 「加我微信 / 发你邮箱」 |
| 「主页有整理好的清单」 | 「GitHub 搜 xxx」「站外链接」 |

### 6.2 私信只能被动响应

私信不是不能回，但**不能在公开内容里承诺「私发」**——一旦承诺，就是 R05 站外引流 + R12 诱导互动双命中。

对方主动来问时，正常聊、正常回答即可，别在私信里发付款码、二维码、压缩包。

### 6.3 对方问「在哪看」怎么回

| 对方问 | 回 |
|---|---|
| 「在哪看」 | 「我整理成清单了，这两天放到主页合集，关注一下就能看到」 |
| 「能不能发我」 | 「合集还没整理完，弄好会发出来，先关注吧」 |
| 「求仓库」 | 「评论区聊就行，我看到了会回」 |
| 「加个微信」 | 不回，或「这里聊就好」 |

### 6.4 真正想长期承接，走这三条

1. **粉丝群**（1000 粉后开放）——站内，最稳
2. **专栏 / 合集**——站内，可沉淀
3. **小红书店铺**（如果要卖服务）——站内交易
